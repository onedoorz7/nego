# Decision Log

Important product and technical decisions, with reasoning. Newest last.

| # | Decision | Reasoning / alternatives considered |
|---|----------|--------------------------------------|
| 1 | **Next.js App Router + TypeScript + Tailwind + SQLite (`node:sqlite`) + Zod** | The suggested stack, minus Postgres/Supabase for now. `node:sqlite` (Node ≥ 22) removes the native-dependency install pain of `better-sqlite3`; the data layer is a thin repo module so a Postgres migration is mechanical (JSON columns → jsonb). |
| 2 | **Content as JSON files, not DB records** | Fastest possible founder editing loop (edit file → refresh). Zod validates on load; mtime-based cache means no restarts. Admin content editor deferred. |
| 3 | **First playable scenario = used-camera (difficulty 1), not freelance** | Founder decision mid-build: "start simpler than the freelance scenario — start easy and build gradually." Path: camera → freelance → salary. |
| 4 | **The LLM verbalizes; a deterministic policy decides** | Strongest possible version of "the LLM must not be the source of truth": the model is *never asked* to evaluate or produce an offer — accept/counter/walk and every number come from the policy engine, and the prompt contains the already-made decision. This makes reservation breaches and invented offer dimensions structurally impossible rather than merely discouraged. Alternative (LLM proposes → engine validates) was rejected as leakier and harder to test. |
| 5 | **Hidden-info reveals gated by deterministic keyword matching** | Reveal gating feeds scoring, so it must be deterministic and testable. Cost: unusual phrasings can miss. Documented upgrade path: LLM classifies the player's question into topic labels, deterministic code still owns the gate and the score. |
| 6 | **Utilities on an authored 0–100 scale per role** | Authoring reservation/target/BATNA directly in utility space keeps the engine simple and scenario-agnostic. The admin scenario inspector + content tests (ZOPA existence, coherence) catch authoring mistakes. Alternative (author reservation as a concrete offer, derive utility) was friendlier but less general for multi-issue packages. |
| 7 | **Offer-space analysis via exact DP over discretized AI utility** | First implementation (λ-scalarization) only found frontier *corners* when trade-offs are linear (e.g. price), which broke ZOPA detection and would have made AI counters jump between extremes. Utilities are additive across fields, so "best player offer with AI utility ≥ L" is a multiple-choice knapsack — solved exactly at 0.01 utility resolution, cached per scenario. Also yields max-joint, pareto-improvement detection, and integrative counter-offers for free. |
| 8 | **Counter-offers maximize the *player's* utility at the AI's demanded level** | This single rule produces realistic logrolling (the AI throws in what's cheap for it) without any scripted trade logic — integrative behavior emerges from the preference structures. |
| 9 | **Variation via seeded RNG over authored ranges** | The "infinite games" pillar: AI reservation/target, opening aggressiveness, and turn limit sampled per session (mulberry32). Reproducible from (scenario, seed) — the foundation for deterministic test fixtures and future "daily challenge" seeds. |
| 10 | **Phases derived from state, not authored** | explore (no offers yet) → bargain (offers live) → close (near turn limit). Authoring phases per scenario was rejected as overbuild; the policy already behaves differently by phase (patience, closing pressure). |
| 11 | **Scripted events with `threshold_delta`** | Cheap, deterministic "unknown elements" that create mid-game drama (another buyer appears, HR pings). Effects limited to threshold shifts + prompt notes for v1. |
| 12 | **Mock provider as a first-class citizen** | The entire game must run with zero API keys: enables offline demo, deterministic tests, and a graceful fallback when live calls fail (game never breaks mid-session). |
| 13 | **Guardrail scanner + retry + fallback, log-first** | Live dialogue is schema-validated, scanned for meta/internal leaks and verbatim hidden-fact leaks, retried once, then falls back to templates. All calls logged to `model_calls` (visible in admin) per the "make failures visible" requirement. Paraphrase-level leak detection is a known gap, documented. |
| 14 | **Reveal IDs double-filtered** | The provider may only claim reveals the policy allowed; the session engine re-filters anyway (defense in depth, tested with a rogue provider). |
| 15 | **Debrief = full role reveal** | After the game, the player sees the AI's brief, all hidden info (found/missed), the AI's utility, and any pareto-better package. This is the chess-style "review your game" moment and the core learning payoff; secrecy only matters mid-game. |
| 16 | **Six scores, each labeled `objective` or `rule_based`; LLM coaching labeled subjective** | Transparency requirement from the spec. No composite "you won/lost". Weights (30/20/15/15/10/10) are explicit product assumptions, documented in scoring-framework. |
| 17 | **Quiz grading server-side** | Lesson API strips `answer_index`/explanations; answers never reach the client. Trivial but establishes the pattern of the server owning truth. |
| 18 | **Progress as a single KV row (single local user)** | Single-founder stage; auth and multi-user storage deferred to Phase 4. Progress engine is behind an interface so swapping storage is contained. |
| 19 | **Unlocking: pass quiz → next lesson; scenarios unlock with their lesson; `NEGO_UNLOCK_ALL=1` override** | Duolingo-style gradient with a founder escape hatch. Deliberately lightweight (no lives/streaks/economy). |
| 20 | **Model default `claude-opus-4-8`, structured outputs via `messages.parse` + Zod, low effort for dialogue** | Dialogue is short and latency-sensitive (effort low); coaching uses default effort. Model/provider configurable by env. |
| 21 | **Docs + lessons + advanced scenarios authored by parallel agents against a frozen schema, then machine-validated** | The Zod schema + exemplar files were written first as the contract; content tests (schema parse, ZOPA existence, option coverage, answer indices) gate everything regardless of author. |
